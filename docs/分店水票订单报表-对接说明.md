# 分店水票订单报表 — 对接说明（另一套 App / 后台）

本文供 **水站管理端、配送端、财务端** 等与 **同一 Supabase 项目** 对接的开发使用，用于实现 **按分店统计水票使用金额与张数**、总店汇总等报表。

---

## 1. 数据源概览

| 优先级 | 表名 | 用途 |
|--------|------|------|
| **主表** | `voucher_usage_ledger` | 每笔订单扣水票产生的**流水**（含冲销）。按 `branch` 汇总即可得到「分店维度的用票金额/张数」。 |
| 关联 | `orders` | 订单状态、送达日、配送日等；与流水通过 `order_id` 逻辑关联。 |
| 关联 | `products` | 商品名称、规格；与流水通过 `product_id`。 |
| 关联 | `customers` | 客户信息；与流水通过 `customer_id`。 |
| 可选 | `voucher_purchase_requests` | 客户**购买**水票的记录（收入侧对账）；与「用票报表」不同维度，见文末。 |

**核心原则**：报表以 **`voucher_usage_ledger`** 为准统计「水票被用掉多少、按何单价计入」；不要仅从 `orders` 推断用票张数。

---

## 2. 表 `voucher_usage_ledger`（必看）

### 2.1 业务含义

- **正数行**：订单成功扣减水票时写入；`voucher_qty > 0`，`line_amount > 0`。
- **负数行**：订单被取消且原单存在正数流水时，写入**冲销**（同订单、同计价结构取负）。
- **`branch`**：写入时从客户资料快照，**不随客户后来改网点而变**，适合按「当时服务网点」出账。

### 2.2 字段一览

| 列名 | 类型 | 说明 |
|------|------|------|
| `id` | uuid | 主键 |
| `order_id` | uuid | 对应 `orders.id`。**表上无外键**，订单可能被删除，报表建议 `LEFT JOIN orders` |
| `customer_id` | uuid | FK → `customers.id` |
| `branch` | text | **分店标识**（与下单时一致），报表 **GROUP BY branch** 的核心字段 |
| `product_id` | uuid | FK → `products.id`，水票按商品维度区分 |
| `voucher_qty` | integer | 张数，**冲销为负** |
| `unit_amount` | integer | 单张水票计价（**印尼盾 IDR，整数**） |
| `line_amount` | integer | `voucher_qty * unit_amount`（冲销为负） |
| `pricing_basis` | text | `purchase_weighted_avg` / `package_fallback` / `zero_unknown` |
| `created_at` | timestamptz | 流水写入时间（扣票或冲销时刻） |

### 2.3 `pricing_basis`（单价从哪来）

| 值 | 含义 |
|----|------|
| `purchase_weighted_avg` | 该客户该商品在 `voucher_purchase_requests` 中 `status = 'confirmed'` 的加权：`floor(sum(amount_paid) / sum(qty))` |
| `package_fallback` | 无确认购买记录时，用 `voucher_packages` 中该商品 active 套餐按 `sort_order` 第一条的 `floor(price/qty)` |
| `zero_unknown` | 无购买且无套餐：`unit_amount = 0`（报表可过滤或单独列出） |

---

## 3. 与 `orders` 的衔接

- 关联条件：`voucher_usage_ledger.order_id = orders.id`（**LEFT JOIN**，因订单可能已删）。
- 常用订单字段：
  - `status`：`pending` / `scheduled` / `delivered`
  - `delivery_date`、`delivered_date`（是否送达、业务上「归属哪个月」常以**送达**为准时需用到）
- **按「流水入账月」统计**：用 `voucher_usage_ledger.created_at`。
- **按「订单送达月」统计**：`JOIN orders` 后用 `orders.delivered_date`（注意 `NULL` 未送达）。

## 4. SQL 示例（可直接改条件使用）

时区示例：**雅加达** `Asia/Jakarta`。请与贵司财务口径统一。

### 4.1 某分店、某自然月 — 用票净额与张数

```sql
-- 参数：分店名、年、月（按流水创建时间落在该月）
SELECT
  SUM(l.line_amount) AS net_amount_idr,
  SUM(l.voucher_qty)  AS net_vouchers
FROM voucher_usage_ledger l
WHERE l.branch = '你的分店标识'  -- 与 customers.branch / 下单快照一致
  AND (l.created_at AT TIME ZONE 'Asia/Jakarta') >= TIMESTAMPTZ '2026-03-01 00:00:00+07'
  AND (l.created_at AT TIME ZONE 'Asia/Jakarta') <  TIMESTAMPTZ '2026-04-01 00:00:00+07';
```

### 4.2 所有分店、按月汇总（总店看板）

```sql
SELECT
  l.branch,
  date_trunc('month', l.created_at AT TIME ZONE 'Asia/Jakarta')::date AS month_jkt,
  SUM(l.line_amount) AS net_amount_idr,
  SUM(l.voucher_qty)  AS net_vouchers
FROM voucher_usage_ledger l
GROUP BY l.branch, date_trunc('month', l.created_at AT TIME ZONE 'Asia/Jakarta')
ORDER BY month_jkt DESC, l.branch;
```

### 4.3 明细分店 + 商品名称 + 订单信息

```sql
SELECT
  l.created_at,
  l.branch,
  p.name AS product_name,
  l.voucher_qty,
  l.unit_amount,
  l.line_amount,
  l.pricing_basis,
  l.order_id,
  o.status AS order_status,
  o.delivered_date,
  o.delivery_date
FROM voucher_usage_ledger l
LEFT JOIN orders o ON o.id = l.order_id
LEFT JOIN products p ON p.id = l.product_id
WHERE l.branch = '你的分店标识'
ORDER BY l.created_at DESC;
```

### 4.4 按订单送达月统计（与 4.1/4.2 的「流水月」不同）

仅统计**已能关联到订单且存在送达日**的行：

```sql
SELECT
  l.branch,
  date_trunc('month', o.delivered_date)::date AS delivered_month,
  SUM(l.line_amount) AS net_amount_idr,
  SUM(l.voucher_qty)  AS net_vouchers
FROM voucher_usage_ledger l
INNER JOIN orders o ON o.id = l.order_id
WHERE o.delivered_date IS NOT NULL
GROUP BY l.branch, date_trunc('month', o.delivered_date)
ORDER BY delivered_month DESC, l.branch;
```

## 5. 权限（RLS）

- `voucher_usage_ledger` 已启用 **RLS**；默认 **anon / 普通 authenticated** 若无策略则**不可读**。
- 推荐：**后台服务**使用 **service role** 查询；或在 Supabase 为「员工角色」配置 `SELECT` 策略（按 `branch` 限制分店账号仅看本店，需自定义 JWT 声明或映射表）。

---

## 6. 边界与注意

| 情况 | 说明 |
|------|------|
| 上线前历史订单 | 无 `voucher_usage_ledger` 行，报表**不包含**旧单用票；仅新产生扣票后有流水。 |
| 订单删除 | `order_id` 仍保留在流水中；`LEFT JOIN orders` 时 `orders` 侧为 `NULL`。 |
| 冲销 | 取消成功会产生负数行；**净额**应用 `SUM(line_amount)`、`SUM(voucher_qty)`。 |
| 客户 App 取消 | 客户端已不提供取消；员工端若调用 `cancel-order`，仍会产生冲销（与现网一致）。 |

---

## 7. 与「购票收入」报表的区别

| 维度 | 表 | 说明 |
|------|-----|------|
| **用票 / 履约侧（分店报表）** | `voucher_usage_ledger` | 体现「在订单里抵扣了多少张、按何单价计入划账」 |
| **购票 / 收款侧** | `voucher_purchase_requests`（`status = 'confirmed'`） | 客户向总店付款买套餐；与用票流水是两条线，对总账时需各自口径 |

若需「购买 vs 使用」联合分析，可在应用层用 `customer_id` + `product_id` + 时间窗口关联，**无强制 DB 外键**。

## 9. 对接检查清单（另一套 App）

1. 使用 **service role** 或已授权的后端代理查询 `voucher_usage_ledger`。  
2. 确认报表口径：**流水月**（`created_at`）还是 **送达月**（`orders.delivered_date`）。  
3. `branch` 字符串与主数据一致（大小写、空格与主档统一）。  
4. 金额单位为 **IDR 整数**，与 `amount_paid` 一致。  
5. 分店账号若需行级权限，在 RLS 或应用层按 `branch` 过滤。
