# 送水订单系统 - 流程与业务逻辑

> 本文档描述客户端 (Customer End) 送水订单系统的认证流程、业务逻辑与数据模型，供后续开发参考。

---

## 一、系统架构概览

- **客户端 (Customer End)**：本仓库，供终端客户使用（下单、查看订单、购买 voucher 等）
- **水站管理端 (Water Depot)**：独立项目，供销售/运营使用（客户管理、订单调度、branch 分配等）
- **共享 Supabase 项目**：客户端与管理端连接同一 Supabase 项目（water depot 项目 `jzdnvdebwmuebjbergsp`）

## 二、认证流程

### 2.1 入口：登录页 (`/` 或 `/login`)

用户输入 **WhatsApp 号码**，调用 `auth-check-device-login` Edge Function。

### 2.2 设备绑定检查 (`auth-check-device-login`)

| 条件 | 行为 |
|------|------|
| `(device_id, whatsapp)` 已绑定 | 直接返回 `customer` + `auth_token`，前端写入 sessionStorage，跳转 `/customer-home` |
| 客户存在但未绑定 | 返回 `needs_otp: true`，前端跳转 `/reauth` 进行 OTP 验证 |
| 客户不存在 | 返回 `new_customer: true`，前端显示「请先注册」并引导至 `/register` |

### 2.3 新客户注册 (`/register`)

1. 填写：姓名、地址、WhatsApp（可预填）
2. 调用 `auth-send-otp` 发送 OTP 到 WhatsApp
3. 输入 OTP 后调用 `auth-verify-otp`，参数 `isRegistration: true`，并传入 `name`、`address`
4. 后端创建客户记录：
   - `customer_type: 'pre_pay'`
   - `voucher_balance: 5`（新客户赠送）
   - `branch: 'Pending'`（待销售分配）
   - 生成 `auth_token`，创建 `device_whatsapp_bindings` 绑定
5. 生产环境发送欢迎 WhatsApp；开发环境跳过

### 2.4 老客户 OTP 验证 (`/reauth`)

1. 输入 WhatsApp（可来自 URL 参数）
2. 调用 `auth-send-otp` 发送 OTP
3. 输入 OTP 后调用 `auth-verify-otp`，参数 `isRegistration: false`
4. 后端更新 `last_login_at`，创建/更新设备绑定
5. 返回 `customer`，前端写入 sessionStorage，跳转 `/customer-home`

### 2.5 Magic Link 登录 (`/home?token=xxx`)

1. 前端调用 `auth-validate-token` 校验 token
2. 若 token 过期：返回 `reauth_required`，跳转 `/reauth`
3. 若有效：写入 sessionStorage，跳转 `/customer-home`

### 2.6 会话存储 (sessionStorage)

- `authenticated`: `'true'`
- `customer`: JSON 对象（id, name, address, whatsapp, customer_type, voucher_balance, branch, discount）
- `auth_token`: UUID（用于 Magic Link 刷新等）

## 三、客户类型 (customer_type)

| 类型 | 说明 | 下单条件 | 支付方式 |
|------|------|----------|----------|
| `pre_pay` | 预付费个人客户 | 需 `voucher_balance > 0` 且 `branch !== 'Pending'` | 使用 voucher 抵扣 |
| `later_pay` | 后付费企业客户 | 需 `branch !== 'Pending'` | 月结/发票 |

**注意**：数据库 schema 中可能仍存在 `pre_paid`/`later_paid` 旧值，代码统一使用 `pre_pay`/`later_pay` 与 water depot 对齐。

---

## 四、Branch（服务网点）

- 新客户默认 `branch: 'Pending'`
- 销售在水站管理端分配 branch 后，客户才能下单
- `canOrder = customer.branch && customer.branch !== 'Pending'`
- 当 `branch === 'Pending'` 时，Order Delivery 按钮禁用，显示「Pending Setup」

---

## 五、订单流程

### 5.1 订单状态 (orders.status)

| 状态 | 说明 |
|------|------|
| `pending` | 待确认，客户可编辑、删除 |
| `scheduled` | 已排期，不可编辑 |
| `delivered` | 已送达 |

### 5.2 支付状态 (orders.payment_status)

| 状态 | 说明 |
|------|------|
| `unpaid` | 未支付（`later_pay` 客户或待付款） |
| `paid` | 已支付（`pre_pay` 客户扣 voucher 后） |

### 5.3 订单创建与编辑

- 订单创建/编辑逻辑主要在水站管理端完成
- 客户端 `/place-order` 用于查看、编辑、删除 **pending** 订单
- 编辑：`/place-order?edit={order_id}`
- 删除：先删 `order_items`，再删 `orders`

### 5.4 数据库约束与函数

- `check_voucher_balance(customer_id, vouchers_needed)`：`later_pay` 直接返回 true；`pre_pay` 检查 `voucher_balance >= vouchers_needed`
- `deduct_vouchers(customer_id, vouchers)`：仅对 `pre_pay` 扣减 voucher

## 六、Voucher 系统

### 6.1 适用客户

仅 `pre_pay` 客户可使用 voucher；`later_pay` 客户访问 `/buy-vouchers` 会提示不可用。

### 6.2 购买套餐 (BuyVouchers)

| 套餐 | 数量 | 价格 (IDR) | 节省 |
|------|------|------------|------|
| Single | 1 | 15,000 | - |
| 10 Vouchers | 10 | 140,000 | 10,000 |
| 20 Vouchers | 20 | 270,000 | 30,000 |
| 50 Vouchers | 50 | 650,000 | 100,000 |

### 6.3 使用规则

- 1 voucher ≈ 1 次产品配送
- 下单时通过 `deduct_vouchers` 扣减

## 七、Edge Functions 一览

| 函数 | 用途 |
|------|------|
| `auth-check-device-login` | 检查设备绑定，决定静默登录 / OTP / 注册 |
| `auth-send-otp` | 发送 OTP（Fazpass 或 DEV 模式 1234） |
| `auth-verify-otp` | 验证 OTP，注册或登录，创建设备绑定 |
| `auth-validate-token` | 校验 Magic Link token |
| `auth-check-and-send-link` | 老流程：检查客户并发送 Magic Link |
| `order-confirmation` | 订单确认（当前策略为跳过发送） |

## 八、关键数据表

| 表 | 说明 |
|------|------|
| `customers` | 客户信息，含 customer_type、branch、voucher_balance |
| `orders` | 订单主表 |
| `order_items` | 订单明细 |
| `auth_otps` | OTP 记录（含 request_id 用于 Fazpass 验证） |
| `device_whatsapp_bindings` | 设备与 WhatsApp 绑定 |
| `whatsapp_messages` | WhatsApp 发送日志 |
| `otp_send_log` | OTP 发送频率限制（60 秒/设备） |

## 十、环境与配置

- **Supabase**：`.env` 中 `VITE_SUPABASE_URL_CLOUD`、`VITE_SUPABASE_ANON_KEY_CLOUD` 指向 water depot 项目

- **部署**：`supabase link --project-ref jzdnvdebwmuebjbergsp` 后执行 `supabase functions deploy`
